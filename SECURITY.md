# 🔒 Security Policy

## Поддерживаемые версии

| Версия | Поддержка безопасности |
|--------|------------------------|
| 1.x    | ✅ Активная            |
| < 1.0  | ❌ Не поддерживается   |

## Как сообщить об уязвимости

Если вы нашли уязвимость в:

- серверном парсинге (Cheerio / challenge-резолвер),
- кэшировании (`unstable_cache`, файловый архив),
- обработке пользовательского ввода (поиск, id),
- зависимостях,

**не создавайте публичный Issue**.

Вместо этого напишите на email (замените на реальный):

```
security@example.com
```

или откройте **private security advisory** в GitHub (Security → Advisories → New draft).

В сообщении укажите:

1. Краткое описание уязвимости.
2. Шаги для воспроизведения.
3. Возможный impact (XSS, SSRF, утечка данных, DoS и т.д.).
4. Предлагаемый фикс (если есть).

Мы постараемся ответить в течение **72 часов** и выпустить патч как можно скорее.

## Что не является уязвимостью

- Открытый характер парсинга публичных источников (это by design).
- Отсутствие rate-limit на стороне этого приложения (ограничения должны быть на уровне хостинга / WAF).
- Проблемы самих upstream-источников (streamlivetv.freedev.app / domtv.blyz.ru).

Спасибо, что помогаете делать StreamLive безопаснее!
